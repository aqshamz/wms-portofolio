# Outbound SQL catalog

The outbound flow is:

`Client DO -> validation -> allocation -> wave -> pick -> staging -> check -> pack -> ship -> store delivery/POD`

Files:

1. `01_do_allocation_wave.sql` — DO CRUD, validation evidence, allocation,
   reservation release, wave creation, and pick-task generation.
2. `02_pick_stage_check_pack.sql` — picking execution, short-pick handling,
   staging, checking/rechecking, packing, and package balance movement.
3. `03_shipment_delivery.sql` — multi-DO shipment manifests, driver assignment,
   partial store-delivery/POD events, retry, and policy-controlled returns.

All operational quantities use the item base UOM. Header IDs are generated by
`generate_document_id`; child IDs derive from their header where practical.
Generate proposed movement and balance IDs before atomic posting blocks:

```sql
SELECT generate_document_id('MOVEMENT', NULL, :warehouse_code, :business_date);
SELECT generate_document_id('INVENTORY_BALANCE', NULL, :warehouse_code, :business_date);
SELECT generate_document_id('RESERVATION', NULL, :warehouse_code, :business_date);
SELECT generate_document_id('OUTBOUND_VALIDATION', NULL, :warehouse_code, :business_date);
```

For every explicit `BEGIN` block, commit only when the final statement returns
the expected row. Otherwise roll back. A missing result normally means stale
workflow state, insufficient stock, a failed validation, or a concurrent worker.

Allocation increases `reserved_qty` but does not reduce `on_hand_qty`. Picking
reduces both source on-hand and reserved quantity, then creates staging stock.
Shipment removes packed stock from the warehouse. Delivered stock stays outside
warehouse inventory; an undelivered return creates a new warehouse balance and
an immutable `DELIVERY_RETURN` movement.

A failed check creates immutable exception records. Corrections link to their
inventory movements; replacement work links to new reservations and pick tasks;
approved short closure is recorded separately. Rechecking is unavailable until
all exceptions from the failed parent check are resolved.

Every owner/warehouse used for delivery returns must have an active
`outbound_return_policy`. Its inventory status must be non-allocatable.
